This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Public marketing site + blog for Quintero Systems Inc. (<https://quintsys.com/>),
a **static site generated by Jekyll** and deployed to Firebase Hosting.

The entire Jekyll project — including the `Gemfile`, `package.json`, and all
source — lives in `jekyll/`. The repository root holds only `README.md`,
`LICENSE`, and `.github/`. **Run every build/serve command from `jekyll/`.**
(The root-level commands in `README.md` are inaccurate; there is no root
`Gemfile`.)

## Toolchain

- Ruby **2.7.2** (pinned in `jekyll/.ruby-version`; RVM gemset `quintsys.com`
  in `.ruby-gemset`). Jekyll `~> 4.3`.
- Node for SASS/asset deps (Bootstrap 4, jQuery, popper.js) via `yarn`.

## Commands (run from `jekyll/`)

```bash
bundle install && yarn install          # first-time setup
bundle exec jekyll serve                # local preview with live reload
bundle exec jekyll build JEKYLL_ENV=production   # production build → _site/
bundle exec htmlproofer ./_site         # link/HTML validation (html-proofer)
```

Deploy (from repo root, after a production build):

```bash
firebase deploy
```

Note: `firebase.json`/`.firebaserc` are **not** checked into this repo — Firebase
deploy config is managed outside version control. Do not assume `firebase deploy`
is runnable without that local config.

## Architecture / conventions specific to this repo

- **Layout chain:** everything inherits from `_layouts/default.html`, which
  pulls in `_includes/head.html`, `navigation.html`, and `google-analytics.html`.
  Content layouts are `home.html` (landing, used by `index.md`) and `post.html`
  (blog posts). `blog.html` is the post index and iterates `site.posts` directly.

- **Blog posts** go in `jekyll/_posts/` named `YYYY-MM-DD-slug.md`. Required
  front matter: `layout: post`, `author`, `title`, and a `tags` list. Permalinks
  are `pretty` (`_config.yml`).

- **Tag pages are auto-generated — do not hand-create them.** The custom plugin
  `_plugins/post_tags.rb` hooks `:posts, :post_write` and writes a stub
  `_tags/<tag>.md` for any tag on a post that doesn't already have one. When
  adding a post with new tags, the corresponding `_tags/*.md` files will appear
  as generated output.

- **Styling:** single entry point `assets/css/main.scss` selectively `@import`s
  individual Bootstrap 4 SCSS partials (functions, variables, mixins, reboot,
  grid, buttons, etc.) rather than all of Bootstrap — keep imports curated, and
  add the matching partial when using a new Bootstrap component. SASS/asset load
  paths include `node_modules` (`_config.yml`).

- **PWA:** the site ships a service worker (`jekyll/sw.js`) and
  `site.webmanifest` with icons in `assets/icons/`. Update `sw.js` cache
  references when asset paths change.

- **SEO/feeds:** driven by `jekyll-seo-tag`, `jekyll-feed`, and `jekyll-sitemap`
  plugins; site-wide metadata (title, tagline, social links) lives in the top of
  `_config.yml`.

- **Dependabot** (`.github/dependabot.yml`) tracks the `/jekyll` bundler + npm
  manifests and root github-actions weekly.
